## 实现与验收合同

1. 机械移动 102 个测试到十个领域模块，根文件只编排；不复制、删除、合并或改名。
2. 通用 support 与 recoverable support 分责；prepared-runtime 继续存在并改接唯一 support。
3. recoverable hooks 收敛成单一线程安全 `RecoverableBehaviorHooks` impl 和显式计数访问器；消除重复
   Thread binding/identity fixture，同时保留显式行为数据。
4. 保存前后 `cargo test --package skiff-runtime-service-db --lib -- --list`，按函数名集合与属性静态双射；确认
   根 102 + prepared 11、唯一 ignore，默认 suite 中该测试仍 ignored。
5. 使用独立 `CARGO_TARGET_DIR=/Users/geek/workspace/skiff-rust-test-service-db/build/cargo-target` 运行：
   `cargo fmt --all -- --check`（至少覆盖 crate）、
   `cargo test --package skiff-runtime-service-db --lib --no-fail-fast`、前后 list；运行 `git diff --check`。
   不运行 ignored live Mongo，不运行 full verify。
6. result 记录命令、退出码、测试双射、实际映射/写集、提交/tree 与 clean 状态。建议机械拆分和 fixture 语义改造分开提交。

风险为中等。最早风险探针是拆分后的静态测试函数/属性双射和 crate 编译；任何 test/ignore 丢失、support 双 owner、
prepared-runtime 接线断裂必须在交接前闭合。若需要生产修改、公共契约变化、兄弟 ownership、设计选择、外部/live
权限，立即以 `TASK_SCOPE_EXPANDED` 停止；baseline 或 DAG 变化先协调主 Agent。

证据只对本分支最终提交代码状态有效；源码、测试属性、manifest/依赖、构建环境或 baseline 改变会使相应证据失效。
